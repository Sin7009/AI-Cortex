# Docker Instructions for AI-Cortex

Этот документ описывает процесс запуска бота AI-Cortex с использованием Docker.

## Предварительные требования

1.  **Docker** и **Docker Compose** должны быть установлены на сервере.
2.  **Ollama** должна быть установлена и запущена на хост-машине (не в контейнере).
    - Убедитесь, что модель загружена: `ollama pull llama3.2` (или другая из вашего `.env`).
    - Ollama должна слушать порт 11434.

## Быстрый запуск

1.  **Настройте окружение:**
    Убедитесь, что файл `.env` существует и заполнен корректно. Если нет, создайте его на основе `.env.example` или запустите `setup_debian12.sh`.

2.  **Соберите и запустите контейнер:**
    ```bash
    docker compose up -d --build
    ```
    Флаг `-d` запускает контейнер в фоновом режиме.

3.  **Проверка работы:**
    Посмотрите логи контейнера, чтобы убедиться, что бот успешно запустился и подключился к Ollama:
    ```bash
    docker compose logs -f
    ```
    Вы должны увидеть сообщение: `✅ Ollama провайдер успешно инициализирован...`.

## Управление

- **Остановить бота:**
  ```bash
  docker compose down
  ```

- **Перезапустить бота:**
  ```bash
  docker compose restart
  ```

- **Обновить код и пересобрать:**
  ```bash
  git pull
  docker compose up -d --build
  ```

## Важные детали

- **База данных (ChromaDB):** Данные сохраняются в Docker volume `chroma_db_data`. Это означает, что "память" бота сохраняется между перезапусками контейнера.
- **Ollama:** Контейнер настроен на подключение к Ollama на хост-машине через адрес `http://host.docker.internal:11434`. В `docker-compose.yml` для этого используется настройка `extra_hosts`.
- **Knowledge Base:** По умолчанию файлы из `knowledge_base` копируются в образ при сборке. Если вы хотите добавлять файлы в базу знаний "на лету" без пересборки, раскомментируйте соответствующую строку в `docker-compose.yml`.

## Устранение неполадок

**Ошибка: Connection refused to Ollama**
- Убедитесь, что Ollama запущена на хосте: `systemctl status ollama`
- Проверьте, что Ollama слушает не только localhost, если у вас специфичные настройки сети (по умолчанию `host.docker.internal` работает через шлюз, так что стандартной настройки Ollama `127.0.0.1` обычно достаточно, так как docker gateway пробрасывает трафик, но иногда может потребоваться `OLLAMA_HOST=0.0.0.0` в настройках сервиса Ollama, если `host-gateway` не отрабатывает).
    - *Примечание:* В большинстве стандартных установок Docker на Linux с `host-gateway` это работает "из коробки".

**Ошибка: Не найден токен Telegram**
- Проверьте файл `.env`. Он должен быть в той же папке, где вы запускаете `docker compose`.
